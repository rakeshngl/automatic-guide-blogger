Umami Analytics

Self-host a privacy-first, cookieless web analytics dashboard for your sites using Docker, PostgreSQL, and a free open-source stack — no data leaves your VPS.

Welcome to another official UVF IT enterprise deployment blueprint. Third-party analytics scripts slow your site down and leak visitor data to ad networks — this guide replaces all of that with one small container.

Today we deploy Umami, an open-source alternative to Google Analytics. It stores every pageview in your own PostgreSQL database, respects GDPR by default, and gives you a clean dashboard at https://analytics.yoursite.com.

⚠ Read this before you pick this architecture

  • Stays on your machine: all pageview records, the PostgreSQL database, and the Umami UI.
  • Leaves your machine: nothing during normal operation — visitors only talk to your server.
  • Want zero-maintenance backups? Add the scheduled pg_dump cron from Phase 4 before going live.
System Architecture Blueprint: Self-Hosted Analytics Pipeline
1

Phase 1: Prepare the VPS

Any 1 vCPU / 1 GB Ubuntu 22.04 box works. Install Docker and create a workspace:

sudo apt update && sudo apt install -y docker.io docker-compose-plugin
# workspace for the stack
mkdir -p /opt/umami && cd /opt/umami
2

Phase 2: The Docker Compose Stack

Create docker-compose.yml with three services wired on a private network:

docker-compose.yml

services:
  umami:
    image: ghcr.io/umami-software/umami:postgresql-latest
    environment:
      # the DB URL uses the service name 'db' as hostname
      DATABASE_URL: postgresql://umami:strongpass@db:5432/umami
      HASH_SALT: change-me-to-random-string
    depends_on: [db]
    restart: unless-stopped
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: umami
      POSTGRES_PASSWORD: strongpass
      POSTGRES_DB: umami
    volumes:
      # named volume survives restarts and redeploys
      - pg_data:/var/lib/postgresql/data
    restart: unless-stopped
volumes:
  pg_data:
docker compose up -d
3

Phase 3: First Login and Site Registration

Browse to port 3000, sign in with the default account, and add your first website.

The tracker snippet looks like this — paste it before </head> on your site:

<script defer src="https://analytics.yoursite.com/script.js" data-website-id="YOUR-ID"></script>
4

Phase 4: Nightly Backups

Schedule a compressed dump so a lost volume never means lost history:

/etc/cron.d/umami-backup

0 2 * * * root docker exec umami-db-1 pg_dump -U umami umami | gzip > /opt/backups/umami-$(date +\%F).sql.gz

Verifying the Stack

CheckCommand / Why it matters
Stack is actually runningdocker compose ps — both services must show Up, not Restarting.
Database is persistingRestart containers, then confirm yesterday's pageviews still appear — proves the named volume works.
Port isn't publicFrom another machine, curl http://<vps-ip>:5432 should fail — PostgreSQL stays internal to the compose network.
Backups existls /opt/backups after 02:00 — a .sql.gz file must be present and non-empty.

What's Actually Private Here

Every analytics event lives inside your own PostgreSQL volume; Umami sets no tracking cookies and never phones home. Your only external dependency is the public DNS record pointing visitors at your VPS — everything else is yours.
