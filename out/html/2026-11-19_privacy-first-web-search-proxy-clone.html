Privacy‑First Web‑Search Proxy Clone

A minimal FastAPI proxy that forwards queries to DuckDuckGo without logging IPs

Welcome to another official UVF IT guide! In this quick‑fire tutorial we’ll build a tiny privacy‑first search proxy inspired by Tabstack, letting you query the web without exposing your own IP address to the search engine.

You’ll have a working FastAPI service in under 45 minutes, using only Python, FastAPI and SQLite – all free and open‑source.

Before you start

  • You need Python 3.9+ and git installed; older versions may cause dependency issues.
  • The clone only forwards GET requests to DuckDuckGo’s HTML endpoint – no JavaScript rendering, so results are plain text snippets.
  • Running on localhost means your own IP is still visible to the upstream search engine; true privacy requires a cloud host or VPN.

Phase 1: Scaffold the project

Create a virtual environment and install FastAPI, Uvicorn and a tiny SQLite ORM (SQLModel). This gives us an isolated Python runtime and the libraries we need to serve HTTP and persist logs.

Initialize a Git repo to keep things tidy, so you can track changes and share the project later.

source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install fastapi uvicorn sqlmodel
git init
git add .
git commit -m "Initial scaffold"
2

Phase 2: Define the data model

A single SearchLog table records the query string and timestamp – useful for demo analytics and showing that we can store data without persisting any personal identifiers.

SQLModel lets us declare the model with standard Python type hints, and it will create the SQLite schema automatically when we first use it.

models.py

from datetime import datetime
from sqlmodel import Field, SQLModel

class SearchLog(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    query: str = Field(index=True, max_length=255)
    timestamp: datetime = Field(default_factory=datetime.utcnow)
3

Phase 3: Core proxy endpoint (API & UI)

In this step we create the heart of the clone: a FastAPI route that receives a search term, stores it for audit, forwards the request to DuckDuckGo’s HTML endpoint, and streams the raw HTML back to the client. Storing the query in SQLite gives us a simple audit log without any external services, keeping the app lightweight and privacy‑focused. The endpoint also serves a minimal HTML page when accessed without a query, offering a tiny UI for manual testing.

We use the httpx library for async HTTP calls because it integrates nicely with FastAPI’s async nature. The response from DuckDuckGo is returned unchanged, so users see the familiar search results while our server never logs their IP address—only the query string we deliberately store.

main.py

import sqlite3
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import HTMLResponse, Response
import httpx

app = FastAPI()

# Initialise SQLite DB (creates file if missing)
conn = sqlite3.connect('queries.db')
cur = conn.cursor()
cur.execute('CREATE TABLE IF NOT EXISTS searches(id INTEGER PRIMARY KEY AUTOINCREMENT, query TEXT, ts DATETIME DEFAULT CURRENT_TIMESTAMP)')
conn.commit()

DUCKDUCKGO_URL = 'https://html.duckduckgo.com/html/'

@app.get('/search', response_class=Response)
async def search(q: str = None):
    if not q:
        # Simple UI when no query is provided
        return HTMLResponse('<form action="/search" method="get"><input name="q" placeholder="search..."><button type="submit">Search</button></form>')
    # Log the query (no IP stored)
    cur.execute('INSERT INTO searches (query) VALUES (?)', (q,))
    conn.commit()
    # Forward request to DuckDuckGo
    async with httpx.AsyncClient() as client:
        resp = await client.get(DUCKDUCKGO_URL, params={'q': q})
        if resp.status_code != 200:
            raise HTTPException(status_code=502, detail='Upstream error')
        return Response(content=resp.content, media_type='text/html')
4

Phase 4: Run locally

Now that the API is ready, we launch it with Uvicorn, FastAPI’s recommended ASGI server. The --reload flag watches source files and restarts automatically, which is handy during development. Once the server is up, you can test the endpoint directly in a browser or via curl.

If you prefer a virtual environment, activate it before running the command to ensure the correct dependencies are used.

uvicorn main:app --reload
5

Phase 5: Verify and extend

After sending a few queries, confirm that they are persisted in the SQLite database. The simple sqlite3 CLI lets you inspect the searches table and see timestamps for each request. From here you can expand the project: add a nicer front‑end, implement rate‑limiting, or deploy to a cloud provider with HTTPS termination for full production readiness.

sqlite3 queries.db "SELECT id, query, ts FROM searches ORDER BY ts DESC LIMIT 5;"
