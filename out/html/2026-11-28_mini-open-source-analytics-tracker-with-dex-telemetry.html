Mini Open‑Source Analytics Tracker with Dex Telemetry

Open‑source Datadog‑style analytics in 45 minutes

Welcome to another official UVF IT guide where we build a lean analytics tracker inspired by Dex Telemetry. You’ll get a tiny backend that records page‑view events and a simple UI to list them – all on your laptop with free tools.

In just five short phases we’ll scaffold a Flask app, define a SQLite model, expose a tiny JSON API, add a minimal HTML dashboard, and run it locally to see real data flowing.

Before you start…

  • You need Python 3.9+ and pip installed; older versions may miss f‑string support.
  • The clone stores data locally in SQLite – no real‑time aggregation or alerting like the full Dex product.
  • Running on Windows may require python -m venv venv instead of python3 -m venv venv.

Phase 1: Scaffold the project

Create a fresh virtual environment so our dependencies stay isolated from any system packages. Then install Flask for the web server and SQLAlchemy to talk to SQLite – these two libraries give us a tiny yet powerful stack.

We also lay out a simple folder layout: a top‑level app package for code, a templates folder for HTML, and a static folder for any CSS or JS you might add later. This structure mirrors typical Flask projects and makes later phases easy to follow.

python3 -m venv venv
source venv/bin/activate  # on Windows use: venv\Scripts\activate
pip install --upgrade pip
pip install Flask SQLAlchemy
mkdir -p app/templates app/static
touch app/__init__.py app/models.py app/routes.py

Phase 2: Define the data model

Our analytics need only one table: Event. It records a unique identifier, the URL path that was visited, and the exact time the event happened. SQLite stores everything in a single file, so we don’t need any external database server.

Using SQLAlchemy’s declarative base keeps the model definition concise and lets Flask create the tables automatically when the app starts for the first time.

app/models.py

from datetime import datetime
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class Event(db.Model):
    __tablename__ = 'events'
    id = db.Column(db.Integer, primary_key=True)
    path = db.Column(db.String(255), nullable=False)
    timestamp = db.Column(db.DateTime, default=datetime.utcnow, nullable=False)

    def __repr__(self):
        return f"<Event {self.id} {self.path} @ {self.timestamp}>"

Phase 3: Build API & UI routes

In this step we wire up the core HTTP endpoints of our telemetry service. The POST /track route accepts a JSON payload describing an event and stores it in an in‑memory list, while GET /events returns the full event log as JSON. Finally, the root / serves a tiny HTML dashboard that lists the captured events in a readable table.

app.py

from flask import Flask, request, jsonify, render_template_string

app = Flask(__name__)

# Simple in‑memory store for demo purposes
EVENTS = []

# HTML template for the dashboard
DASHBOARD_HTML = """
<!doctype html>
<title>Mini Dex Dashboard</title>
<h1>Captured Events</h1>
<table border=1>
<tr><th>Event</th><th>Timestamp</th></tr>
{% for e in events %}
<tr><td>{{ e['name'] }}</td><td>{{ e['ts'] }}</td></tr>
{% endfor %}
</table>
"""

@app.route('/')
def index():
    return render_template_string(DASHBOARD_HTML, events=EVENTS)

@app.route('/track', methods=['POST'])
def track():
    data = request.get_json() or {}
    # Ensure we have a name; default to 'unknown'
    event = {
        'name': data.get('name', 'unknown'),
        'ts': data.get('timestamp', __import__('time').time())
    }
    EVENTS.append(event)
    return jsonify({'status': 'ok'}), 201

@app.route('/events')
def get_events():
    return jsonify(EVENTS)

if __name__ == '__main__':
    app.run(debug=True)
4

Phase 4: Run locally

Now we fire up the Flask development server so you can interact with the API and dashboard on your own machine. The server will bind to 127.0.0.1:5000 by default, which you can reach from a browser or any HTTP client. Keep this terminal open – stopping it will shut down the service.

export FLASK_APP=app.py
flask run
5

Phase 5: Verify & extend

With the server running, send a test event using curl and then refresh the dashboard to see it appear in the table. This confirms both the ingestion endpoint and the UI rendering are working. From here you can enrich events with additional fields, swap the in‑memory list for a real database, or replace the simple HTML with a React front‑end.

curl -X POST http://127.0.0.1:5000/track \
  -H "Content-Type: application/json" \
  -d '{"name": "home", "timestamp": 1700000000}'
