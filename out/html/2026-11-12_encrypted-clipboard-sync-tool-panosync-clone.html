Encrypted Clipboard Sync Tool (Panosync) Clone

Build a minimal end‑to‑end encrypted clipboard sync using Node.js and SQLite

Welcome to another official UVF IT build guide. In the next 45 minutes you’ll create a lightweight clone of Panosync – a self‑hosted relay that syncs clipboard data across devices with end‑to‑end encryption.

We’ll use Node.js, Express, and SQLite on the free tier – no external paid APIs. The result is a local server you can run on any machine and a tiny client script to push/pull encrypted clipboard snippets.

Prerequisites & Gotchas

  • Node ≥ 18 and npm must be installed; older versions lack native Web Crypto support.
  • The clone stores encrypted blobs in SQLite – fine for a demo but not production‑grade. Real Panosync uses a Rust relay for performance.

Phase 1: Scaffold Project

Initialize a new npm project and install the required packages. This gives us a clean workspace and pulls in Express for the HTTP relay, better‑sqlite3 for a tiny SQLite wrapper, and clipboardy for a quick client demo.

We also add nodemon as a dev dependency so the server restarts automatically while you iterate.

All files will live under a single folder, keeping the clone minimal and easy to understand.

Phase 2: Data Model – SQLite Store

Create a tiny SQLite database with a table for encrypted clipboard entries. Each row stores a UUID, the encrypted blob, and a timestamp so we can prune old entries later.

We wrap the raw SQL in a small helper module (db.js) that exposes addEntry, getLatest, and clearOld functions – enough for the relay to push and pull data safely.

db.js

const Database = require('better-sqlite3');
const path = require('path');

// Open (or create) a local SQLite file in the project root
const db = new Database(path.resolve(__dirname, 'clipboard.db'));

// Initialise the table if it doesn't exist yet
const init = db.prepare(`
  CREATE TABLE IF NOT EXISTS entries (
    id TEXT PRIMARY KEY,
    payload BLOB NOT NULL,
    created_at INTEGER NOT NULL
  )
`);
init.run();

// Insert a new encrypted clipboard entry
function addEntry(id, payload) {
  const stmt = db.prepare('INSERT INTO entries (id, payload, created_at) VALUES (?, ?, ?)');
  stmt.run(id, payload, Date.now());
}

// Retrieve the most recent entry (by creation time)
function getLatest() {
  const row = db.prepare('SELECT payload FROM entries ORDER BY created_at DESC LIMIT 1').get();
  return row ? row.payload : null;
}

// Optional: delete entries older than a given age (ms)
function clearOld(maxAgeMs) {
  const cutoff = Date.now() - maxAgeMs;
  db.prepare('DELETE FROM entries WHERE created_at < ?').run(cutoff);
}

module.exports = {addEntry, getLatest, clearOld};
3

Phase 3: API – Push & Pull End‑to‑End Encrypted Data

In this phase we expose two tiny HTTP endpoints that act as a relay for encrypted clipboard blobs. The server never sees the plaintext – it just stores the ciphertext that the client sends. A POST to /push writes a new row, while a GET to /pull returns the most recent blob so any other client can retrieve it.

We keep the implementation lightweight: Express handles routing, SQLite stores the blobs, and we log basic activity so you can see when data moves through the relay. This sets the foundation for end‑to‑end encryption without any complex auth for the minimal clone.

server.js

const express = require('express');
const sqlite3 = require('sqlite3').verbose();
const bodyParser = require('body-parser');

const app = express();
app.use(bodyParser.json({limit:'1mb'}));

// Initialise SQLite DB and table
const db = new sqlite3.Database('relay.db');
db.run('CREATE TABLE IF NOT EXISTS blobs(id INTEGER PRIMARY KEY AUTOINCREMENT, data TEXT NOT NULL, ts DATETIME DEFAULT CURRENT_TIMESTAMP)');

// POST /push – store encrypted blob
app.post('/push', (req, res) => {
  const {blob} = req.body;
  if (!blob) return res.status(400).json({error:'Missing blob'});
  db.run('INSERT INTO blobs(data) VALUES(?)', blob, function(err){
    if (err) return res.status(500).json({error:err.message});
    console.log(`Stored blob id ${this.lastID}`);
    res.json({status:'ok', id:this.lastID});
  });
});

// GET /pull – retrieve newest blob
app.get('/pull', (req, res) => {
  db.get('SELECT data FROM blobs ORDER BY ts DESC LIMIT 1', (err,row)=>{
    if (err) return res.status(500).json({error:err.message});
    if (!row) return res.json({blob:null});
    res.json({blob:row.data});
  });
});

const PORT = 3000;
app.listen(PORT,()=>console.log(`Relay listening on http://localhost:${PORT}`));

Phase 4: Client – Encrypt, Sync, and Clipboard

Now we build the client that talks to the relay, encrypts the clipboard, and writes decrypted data back. We use the same shared secret on every machine – in a real app you’d generate per‑user keys, but a constant keeps the example simple.

The script reads the current clipboard, encrypts it with AES‑256‑GCM, pushes the ciphertext, then pulls the latest blob, decrypts it, and finally overwrites the local clipboard. This round‑trip demonstrates true end‑to‑end encryption: the server only sees the opaque blob field.

client.js

const fetch = require('node-fetch');
const clipboardy = require('clipboardy');
const crypto = require('crypto');

// Shared secret – replace with a strong random string in production
const SECRET = 'super-secret-shared-key-32bytes!!'; // 32 chars = 256 bits
const ALGO = 'aes-256-gcm';
const RELAY = 'http://localhost:3000';

function encrypt(plain){
  const iv = crypto.randomBytes(12);
  const key = crypto.createHash('sha256').update(SECRET).digest();
  const cipher = crypto.createCipheriv(ALGO, key, iv);
  const enc = Buffer.concat([cipher.update(plain,'utf8'), cipher.final()]);
  const tag = cipher.getAuthTag();
  return Buffer.concat([iv, tag, enc]).toString('base64');
}

function decrypt(blob){
  const data = Buffer.from(blob,'base64');
  const iv = data.slice(0,12);
  const tag = data.slice(12,28);
  const enc = data.slice(28);
  const key = crypto.createHash('sha256').update(SECRET).digest();
  const decipher = crypto.createDecipheriv(ALGO, key, iv);
  decipher.setAuthTag(tag);
  const dec = Buffer.concat([decipher.update(enc), decipher.final()]);
  return dec.toString('utf8');
}

async function push(blob){
  await fetch(`${RELAY}/push`,{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({blob})});
}

async function pull(){
  const res = await fetch(`${RELAY}/pull`);
  const json = await res.json();
  return json.blob;
}

(async()=>{
  const raw = await clipboardy.read();
  const encrypted = encrypt(raw);
  await push(encrypted);
  console.log('Pushed encrypted clipboard');
  const latest = await pull();
  if (latest){
    const decrypted = decrypt(latest);
    await clipboardy.write(decrypted);
    console.log('Pulled and updated local clipboard');
  } else {
    console.log('No blob available on server');
  }
})();

Phase 5: Run & Verify

With the relay and client ready, it’s time to see the sync in action. Start the server in one terminal, then run the client on two separate terminals – each will push its clipboard and pull the newest entry from the other side.

If everything works, copying text on one machine will cause the other terminal’s clipboard to update after the client runs. This demonstrates a functional, end‑to‑end encrypted clipboard sync built from scratch.

# Terminal 1 – start the relay server
node server.js &
# Note the PID if you need to stop it later

# Terminal 2 – first client (pushes your current clipboard)
node client.js

# Terminal 3 – second client (pulls and writes the remote clipboard)
node client.js
