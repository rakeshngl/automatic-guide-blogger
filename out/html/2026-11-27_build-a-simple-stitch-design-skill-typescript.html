Build a Simple Stitch Design Skill (TypeScript)

Clone a minimal agent skill using Stitch Skills on your local machine

Welcome to another official UVF IT build guide. In the next 45 minutes you’ll create a tiny TypeScript‑based Stitch Design skill that can be invoked by any Agent Skills‑compatible coding agent.

We’ll use the free, open‑source Stitch Skills repo, a Node 18 runtime, and a local SQLite DB to store a single design request – no paid APIs required.

Before you start…

  • Node ≥18 and npm must be installed globally; older versions will fail to compile TypeScript.
  • The real Stitch Design suite includes many utilities and a remote MCP server – our clone runs entirely locally and only implements a single generateDesign skill.
  • File paths are case‑sensitive on Linux/macOS; copy them exactly as shown.
Minimal Stitch Skill Architecture
1

Phase 1: Scaffold the project

We start by creating a clean npm workspace that understands TypeScript. This gives us a package.json, a tsconfig.json, and a place to install the tiny Stitch SDK we need for the clone.

The scaffold also adds useful dev scripts so you can build and run the skill with a single command, keeping the workflow beginner‑friendly.

mkdir stitch-skill && cd stitch-skill
npm init -y
npm install typescript @types/node --save-dev
npm install @google-labs/stitch-sdk sqlite3
npx tsc --init --rootDir src --outDir dist --esModuleInterop true --resolveJsonModule true
mkdir src
cat > src/index.ts <<'EOF'
import { startServer } from '@google-labs/stitch-sdk';
import { generateDesign } from './skill';

startServer({ generateDesign });
EOF
2

Phase 2: Define the skill model

The skill’s contract is a tiny JSON schema: it receives a prompt string and returns a Markdown design document. Declaring this schema lets the runtime validate incoming requests and type‑check our handler.

We also set up a very small in‑memory store backed by SQLite; the first request will be persisted so you can query it later, demonstrating a realistic data flow without extra complexity.

src/skill.ts

import { SkillHandler } from '@google-labs/stitch-sdk';
import Database from 'sqlite3';

// 1️⃣ Define the input / output shape
export interface DesignRequest {
  prompt: string;
}
export interface DesignResponse {
  markdown: string;
}

// 2️⃣ Simple SQLite wrapper (creates table on first run)
const db = new Database.Database('designs.db');
db.run('CREATE TABLE IF NOT EXISTS designs (id INTEGER PRIMARY KEY AUTOINCREMENT, prompt TEXT, markdown TEXT)');

// 3️⃣ Core skill implementation
export const generateDesign: SkillHandler<DesignRequest, DesignResponse> = async (input) => {
  // Very naive “generation”: echo the prompt as a markdown header
  const markdown = `# Design for: ${input.prompt}\n\n*Generated by minimal Stitch skill*`;
  // Persist the request/response
  db.run('INSERT INTO designs (prompt, markdown) VALUES (?, ?)', [input.prompt, markdown]);
  return { markdown };
};
3

Phase 3: Expose the skill via HTTP

We’ll spin up a tiny Express server that listens for POST requests from an agent and forwards the payload to our design‑generation function. Keeping the HTTP layer separate makes it easy to swap the skill implementation later without touching the networking code.

The server returns a JSON object with a design field so agents can parse the result consistently. All routes are prefixed with /skill to avoid clashes if you add more skills later.

src/server.ts

import express from 'express';
import { generateDesign } from './skill';

const app = express();
app.use(express.json());

// POST /skill/generateDesign expects { prompt: string }
app.post('/skill/generateDesign', async (req, res) => {
  try {
    const { prompt } = req.body;
    if (!prompt) {
      return res.status(400).json({ error: 'Missing prompt in request body' });
    }
    const design = await generateDesign(prompt);
    res.json({ design });
  } catch (err) {
    console.error('Skill error:', err);
    res.status(500).json({ error: 'Internal server error' });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Skill server listening on http://localhost:${PORT}`);
});
4

Phase 4: Run locally

Compile the TypeScript sources into JavaScript and launch the Express wrapper. The npm run build script (defined in package.json) calls the TypeScript compiler, emitting files into the dist folder. Once built, start the server with Node; you should see a friendly log confirming the listening address.

npm run build && node dist/server.js
5

Phase 5: Verify and extend

A quick curl request proves the endpoint is alive and returning the expected shape. If you see a JSON object with a design key, the minimal skill is working! From here you can add persistence (e.g., SQLite) or richer prompts without changing the HTTP wrapper.

curl -X POST http://localhost:3000/skill/generateDesign \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Create a modern logo for a coffee shop"}'
