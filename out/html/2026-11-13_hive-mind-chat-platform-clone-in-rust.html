Hive‑Mind Chat Platform Clone in Rust

A minimal Buzz‑inspired workspace built in 45 minutes

Welcome to another official UVF IT build guide! In this tutorial we’ll spin up a tiny Rust‑based Hive‑Mind chat platform that mimics the core of Buzz – a shared room where humans and simple AI agents exchange messages.

You’ll get a working HTTP server, a SQLite‑backed event log, and a tiny web UI. All tools are free‑tier and open‑source, so you can run everything locally and extend it later.

Before you start

  • You need Rust 1.70+ and Cargo installed; older versions will fail to compile the async‑tokio stack.
  • The clone only stores plain text messages – no cryptographic signatures, reactions, or real AI agents (those are left as exercises).
  • Running on Windows may require the sqlite3 development library; Linux/macOS work out‑of‑the‑box.

Phase 1: Scaffold the project

Create a new Cargo binary project and pull in the async web framework, SQLite driver, and a tiny templating crate in one command. This gives us a clean starting point and ensures all required crates are listed in Cargo.toml before we write any code.

We’ll also enable the tokio runtime feature so the server can run asynchronously without extra boilerplate.

cargo new hive_mind --bin
cd hive_mind
cat >> Cargo.toml <<'EOF'
[dependencies]
warp = "0.3"
tokio = { version = "1", features = ["full"] }
rusqlite = { version = "0.29", features = ["bundled"] }
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
askama = "0.12"
EOF

Phase 2: Data model & SQLite init

Define a Message struct that mirrors the columns we need in the database – an auto‑increment id, a timestamp, a username, and the text body. Then open (or create) a SQLite file and run a CREATE TABLE IF NOT EXISTS statement so the first run always has a place to store messages.

The code lives in src/main.rs and will be the foundation for both the HTTP API and the UI rendering later.

src/main.rs

use rusqlite::{params, Connection, Result};
use serde::{Deserialize, Serialize};
use std::time::{SystemTime, UNIX_EPOCH};

#[derive(Debug, Serialize, Deserialize)]
struct Message {
    id: i64,
    timestamp: i64,
    user: String,
    body: String,
}

fn init_db() -> Result<Connection> {
    let conn = Connection::open("hive_mind.db")?;
    conn.execute(
        "CREATE TABLE IF NOT EXISTS messages (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            timestamp INTEGER NOT NULL,
            user TEXT NOT NULL,
            body TEXT NOT NULL
        )",
        [],
    )?;
    Ok(conn)
}

fn current_ts() -> i64 {
    SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .unwrap()
        .as_secs() as i64
}

fn main() -> Result<()> {
    let _db = init_db()?;
    println!("Database initialized – ready for the server phase.");
    Ok(())
}

Phase 3: API routes (GET/POST)

In this step we expose two HTTP endpoints using Warp. The GET /messages route returns the in‑memory log as JSON, while POST /send accepts a JSON payload with author and content and pushes it onto the log. Keeping the data in a Mutex<Vec<Message>> lets us share state safely across async handlers. These routes form the tiny backend API our UI will talk to.

src/main.rs

use std::sync::{Arc, Mutex};
use warp::Filter;

#[derive(Clone, serde::Serialize, serde::Deserialize)]
struct Message {
    author: String,
    content: String,
}

type Db = Arc<Mutex<Vec<Message>>>;

#[tokio::main]
async fn main() {
    let db: Db = Arc::new(Mutex::new(Vec::new()));

    let db_filter = warp::any().map(move || db.clone());

    // GET /messages -> returns all messages
    let list = warp::path("messages")
        .and(warp::get())
        .and(db_filter.clone())
        .map(|db: Db| warp::reply::json(&*db.lock().unwrap()));

    // POST /send -> adds a new message
    let send = warp::path("send")
        .and(warp::post())
        .and(warp::body::json())
        .and(db_filter.clone())
        .map(|msg: Message, db: Db| {
            db.lock().unwrap().push(msg);
            warp::reply::with_status("ok", warp::http::StatusCode::OK)
        });

    let routes = list.or(send);
    warp::serve(routes).run(([127,0,0,1], 3030)).await;
}

Phase 4: Tiny UI

Now we serve a minimal HTML page that polls the /messages endpoint every second and displays each chat line. A simple form lets the user type an author name and a message, then POSTs the JSON payload to /send. All the logic lives in a few lines of vanilla JavaScript, keeping the UI lightweight and easy to understand.

static/index.html

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Hive‑Mind Mini Chat</title>
  <style>body{font-family:sans-serif;margin:2rem;}#log{border:1px solid #ccc;padding:1rem;height:300px;overflow:auto;}</style>
</head>
<body>
  <h1>Hive‑Mind</h1>
  <div id="log"></div>
  <form id="chatForm">
    <input id="author" placeholder="Your name" required />
    <input id="content" placeholder="Message" required />
    <button type="submit">Send</button>
  </form>
  <script>
    async function fetchLog(){
      const res = await fetch('/messages');
      const msgs = await res.json();
      const log = document.getElementById('log');
      log.innerHTML = msgs.map(m=>`<b>${m.author}:</b> ${m.content}`).join('<br>');
    }
    setInterval(fetchLog, 1000);
    document.getElementById('chatForm').onsubmit = async e=>{
      e.preventDefault();
      const author=document.getElementById('author').value;
      const content=document.getElementById('content').value;
      await fetch('/send',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({author,content})});
      document.getElementById('content').value='';
      fetchLog();
    };
  </script>
</body>
</html>

Phase 5: Run & verify

We now combine the API routes with static file serving so the browser can load the UI directly from the same server. Warp’s fs::dir filter points at the static folder, and we mount it under the root path. Running cargo run starts the service on port 3030; opening http://localhost:3030/ should show the chat UI and let you send messages that appear instantly.

src/main.rs

use std::sync::{Arc, Mutex};
use warp::Filter;

#[derive(Clone, serde::Serialize, serde::Deserialize)]
struct Message { author: String, content: String }

type Db = Arc<Mutex<Vec<Message>>>;

#[tokio::main]
async fn main() {
    let db: Db = Arc::new(Mutex::new(Vec::new()));
    let db_filter = warp::any().map(move || db.clone());

    let list = warp::path("messages")
        .and(warp::get())
        .and(db_filter.clone())
        .map(|db: Db| warp::reply::json(&*db.lock().unwrap()));

    let send = warp::path("send")
        .and(warp::post())
        .and(warp::body::json())
        .and(db_filter.clone())
        .map(|msg: Message, db: Db| {
            db.lock().unwrap().push(msg);
            warp::reply::with_status("ok", warp::http::StatusCode::OK)
        });

    // Serve static files from ./static at the root
    let static_files = warp::fs::dir("static");

    let routes = list.or(send).or(static_files);
    warp::serve(routes).run(([127,0,0,1], 3030)).await;
}
