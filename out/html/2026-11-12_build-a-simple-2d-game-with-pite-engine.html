Build a Simple 2D Game with Pite Engine

A beginner‑friendly clone of a classic 2D arcade game using the free‑tier Pite engine

Welcome to another official UVF IT build guide! In the next 45 minutes you’ll spin up a tiny 2‑D arcade‑style game powered by the open‑source Pite engine—no paid services, just pure Python.

We’ll scaffold a minimal project, add a player sprite, make it move, render a static obstacle, and run the game locally. By the end you’ll have a working prototype you can extend with enemies, scoring, or sound.

Before you start…

  • You need Python 3.10+ and pip installed; older versions may fail to compile Pite’s C extensions.
  • The clone omits advanced features like physics, asset pipelines, and packaging – it’s just a runnable script.

Phase 2: Define the player entity (data/model)

We now create a tiny Player class that loads a sprite image and tracks its x‑y position. Keeping the data in a class makes it easy to extend later (velocity, animation, etc.).

The class lives in game.py, which will later become the entry point for the whole app.

game.py

import os
from pite import Sprite

class Player:
    """Simple player entity holding a sprite and its position."""
    def __init__(self, image_path: str, x: int = 100, y: int = 100):
        # Load the image once; Pite's Sprite handles texture creation.
        self.sprite = Sprite(image_path)
        self.x = x
        self.y = y

    def draw(self, screen):
        """Render the sprite at its current coordinates."""
        screen.blit(self.sprite, (self.x, self.y))

# Quick sanity check – run this file to see no import errors.
if __name__ == "__main__":
    player = Player(os.path.join("assets", "player.png"))
    print(f"Player loaded at ({player.x}, {player.y}) with sprite {player.sprite}")

Phase 3: Add input & main loop (API/UI)

In this step we bind the arrow keys to move our player sprite and start the Pite game loop. The loop continuously polls events, updates the player’s position, and redraws the screen, giving us a responsive interactive window. Keeping everything in a single game.py file makes it easy to follow for beginners.

game.py

import pite

# Create a 400x300 window
win = pite.Window(400, 300, title='UVF IT Pite Demo')

# Player is a simple red square
player = pite.Rect(180, 130, 40, 40, color=(255, 0, 0))

# Movement speed in pixels per frame
speed = 5

while win.is_open():
    # Process input events
    for ev in win.poll_events():
        if ev.type == pite.Event.QUIT:
            win.close()
    # Keyboard state handling
    keys = win.get_keyboard_state()
    if keys[pite.Key.LEFT]:
        player.x -= speed
    if keys[pite.Key.RIGHT]:
        player.x += speed
    if keys[pite.Key.UP]:
        player.y -= speed
    if keys[pite.Key.DOWN]:
        player.y += speed
    # Clear screen and draw player
    win.clear((0, 0, 0))
    win.draw(player)
    win.display()

Phase 5: Verify & extend (optional obstacle)

Now we’ll add a static blue obstacle to show how multiple entities coexist. The obstacle doesn’t move; it simply gets drawn each frame, proving you can manage more than one drawable object.

game.py

import pite

win = pite.Window(400, 300, title='UVF IT Pite Demo')
player = pite.Rect(180, 130, 40, 40, color=(255, 0, 0))
# New static obstacle
obstacle = pite.Rect(100, 80, 60, 60, color=(0, 0, 255))

speed = 5

while win.is_open():
    for ev in win.poll_events():
        if ev.type == pite.Event.QUIT:
            win.close()
    keys = win.get_keyboard_state()
    if keys[pite.Key.LEFT]:
        player.x -= speed
    if keys[pite.Key.RIGHT]:
        player.x += speed
    if keys[pite.Key.UP]:
        player.y -= speed
    if keys[pite.Key.DOWN]:
        player.y += speed
    win.clear((0, 0, 0))
    win.draw(obstacle)  # draw obstacle first
    win.draw(player)    # then player on top
    win.display()
