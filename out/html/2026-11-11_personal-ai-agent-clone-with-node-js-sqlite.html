Personal AI Agent Clone with Node.js & SQLite

A minimal nod‑by‑n8n‑style workflow engine

Welcome to another official UVF IT guide where we roll up our sleeves and build a tiny personal AI agent inspired by Nod by n8n. We'll stitch together a lightweight Node.js server, a SQLite store, and a simple HTTP‑based workflow runner – all in under an hour.

In this clone you’ll get a REST endpoint to trigger a workflow, a tiny SQLite table to persist steps, and a console‑log “agent” that pretends to think. No paid APIs, no cloud functions – just pure local code you can run and extend.

Before you start

  • Node.js ≥ 18 and npm must be installed; older versions lack native fetch support.
  • The real product runs sandboxed code and integrates LLM APIs – our clone only logs messages, so AI capabilities are mocked.
  • SQLite file is created in the project folder; ensure you have write permission.

2

Phase 2: Define data model (SQLite)

Create a tiny SQLite helper that ensures a steps table exists and provides a function to fetch steps for a workflow. This module isolates all database concerns, making the rest of the code simple and testable.

The helper runs once at import, creating the file workflow.db in the project root if it doesn't already exist.

src/db.js

const path = require('path');
const sqlite3 = require('sqlite3').verbose();

// Resolve a DB file next to the project root
const dbPath = path.resolve(__dirname, '..', 'workflow.db');
const db = new sqlite3.Database(dbPath);

// Ensure the steps table exists
const initSql = `
CREATE TABLE IF NOT EXISTS steps (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  workflow TEXT NOT NULL,
  step_order INTEGER NOT NULL,
  action TEXT NOT NULL
);
`;

db.exec(initSql, err => {
  if (err) console.error('Failed to init DB:', err);
});

/**
 * Fetch ordered steps for a given workflow name.
 * @param {string} workflow
 * @returns {Promise<Array<{id:number,action:string}>>}
 */
function getSteps(workflow) {
  return new Promise((resolve, reject) => {
    db.all(
      'SELECT id, action FROM steps WHERE workflow = ? ORDER BY step_order ASC',
      [workflow],
      (err, rows) => (err ? reject(err) : resolve(rows))
    );
  });
}

module.exports = { getSteps };

Phase 3: Mock AI agent

In this step we create a tiny stand‑in for a real large language model. The module exports a single async function that accepts an action string, pretends to think for a moment, and then logs the action with a clear prefix. Keeping it async lets us swap in real network calls later without changing the surrounding code.

src/agent.js

// src/agent.js – mock AI agent
// Export a function that pretends to execute an action.
// It returns a promise so real LLM calls can replace it later.

module.exports = async function mockAgent(action) {
  // Simulate a tiny latency (e.g., network round‑trip)
  await new Promise(res => setTimeout(res, 100));
  console.log(`[Agent] Executing: ${action}`);
  // Return a dummy result – could be expanded to include data.
  return { status: 'ok', performed: action };
};
4

Phase 4: Build API & workflow runner

Now we wire an Express server that can store and run workflows. A workflow is just a named list of step strings saved in SQLite; the server offers a POST /​workflow/:name/steps endpoint to seed steps and a POST /​run/:name endpoint to execute them. When a run is triggered we pull the steps in order, feed each to the mock agent, and wait for completion before responding.

src/index.js

// src/index.js – Express API + runner
const express = require('express');
const sqlite3 = require('sqlite3').verbose();
const mockAgent = require('./agent');

const app = express();
app.use(express.json());

// Initialise SQLite DB (in‑memory for simplicity)
const db = new sqlite3.Database(':memory:');
db.serialize(() => {
  db.run('CREATE TABLE IF NOT EXISTS steps (workflow TEXT, step TEXT, idx INTEGER)');
});

// Seed workflow steps
app.post('/workflow/:name/steps', (req, res) => {
  const { name } = req.params;
  const steps = req.body.steps; // expect array of strings
  if (!Array.isArray(steps)) return res.status(400).json({error:'steps must be array'});
  const stmt = db.prepare('INSERT INTO steps (workflow, step, idx) VALUES (?,?,?)');
  steps.forEach((s,i) => stmt.run(name, s, i));
  stmt.finalize(err => {
    if (err) return res.status(500).json({error: err.message});
    res.json({msg:'seeded'});
  });
});

// Run a workflow
app.post('/run/:name', async (req, res) => {
  const { name } = req.params;
  db.all('SELECT step FROM steps WHERE workflow = ? ORDER BY idx', [name], async (err, rows) => {
    if (err) return res.status(500).json({error: err.message});
    if (!rows.length) return res.status(404).json({error:'no steps'});
    for (const r of rows) {
      await mockAgent(r.step);
    }
    res.json({msg:'completed'});
  });
});

const PORT = 3000;
app.listen(PORT, () => console.log(`Server on http://localhost:${PORT}`));
5

Phase 5: Run locally & verify

Start the server, seed a demo workflow, and then trigger it. The console should show the mock agent logging each step, proving the end‑to‑end flow works. Use curl (or any HTTP client) to hit the two endpoints; the responses confirm the API behaved as expected.

# Install dependencies (run once)
npm install express sqlite3

# Start the server
node src/index.js &
SERVER_PID=$!
# Give it a second to bind
sleep 1

# Seed a simple workflow called "demo"
curl -s -X POST http://localhost:3000/workflow/demo/steps \
  -H "Content-Type: application/json" \
  -d '{"steps":["Say hello","Fetch data","Summarize"]}'

# Trigger the workflow
curl -s -X POST http://localhost:3000/run/demo

# Clean up
kill $SERVER_PID
