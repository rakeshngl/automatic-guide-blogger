Self‑Contained HTML Diagram Viewer Clone

A minimal Node.js + SQLite app that renders SVG diagrams from JSON

Welcome to another official UVF IT build where we craft a tiny diagram viewer inspired by the Diagram Design skill. You’ll spin up a local server that accepts a simple JSON description and returns a single HTML file containing an inline SVG – no external APIs required.

In ~45 minutes you’ll have a working clone you can extend with more shapes or styling, perfect for learning full‑stack basics while creating something visual.

Before you start

  • Node.js ≥ 18 and npm must be installed – older versions lack native fetch support used in the example.
  • The clone only supports rectangles and arrows; the original handles 52 types and branding – you’ll add those later.
  • Running on Windows may require rm -rf to be replaced with rmdir /s /q in the cleanup step.

Phase 1: Scaffold Project

We start by creating a clean directory for the clone, initializing it as an npm project, and pulling in the two runtime dependencies we need: Express for the web server and better‑sqlite3 for a tiny, synchronous SQLite wrapper. All of this fits comfortably in a single shell script so you can repeat it on any machine.

The script also creates a src folder where our server code and future assets will live, keeping the root tidy. After it runs you’ll have a ready‑to‑code workspace and a package.json that tracks the dependencies.

#!/usr/bin/env bash
# Clean start
rm -rf diagram-viewer && mkdir diagram-viewer && cd diagram-viewer
# Initialise npm
npm init -y > /dev/null
# Install runtime deps
npm install express better-sqlite3 > /dev/null
# Create source folder
mkdir -p src
# Verify setup
echo "Setup complete. Files in $(pwd):"
ls -1

Phase 2: Data Model (SQLite)

Our viewer needs a place to store each diagram’s metadata and the raw JSON that describes its shapes. SQLite is perfect for a self‑contained demo because it lives in a single file and requires no external service.

We define a single table diagrams with an auto‑incrementing primary key, a title column for human‑readable names, and a payload column that holds the JSON string. This schema will be executed when the app starts, creating the database file if it doesn’t exist yet.

src/schema.sql

CREATE TABLE IF NOT EXISTS diagrams (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    payload TEXT NOT NULL
);
3

Phase 3: Core API & HTML Generator

In this step we wire up an Express server that talks to our SQLite database. When a client requests /view/:id we pull the stored JSON diagram, turn each shape into an SVG fragment, and then embed those fragments inside a tiny self‑contained HTML page. Keeping the HTML generation in one place makes it easy to add CSS or JavaScript later without touching the route logic.

The SVG builder is deliberately simple: it knows how to render rectangles and arrows, the two primitives used in our sample diagram. By returning a full HTML document we ensure the viewer works in any browser without extra assets – perfect for a minimal clone.

src/server.js

const express = require('express');
const sqlite3 = require('sqlite3').verbose();
const path = require('path');

const app = express();
const DB_PATH = path.join(__dirname, '..', 'data', 'diagrams.db');
const db = new sqlite3.Database(DB_PATH);

// Helper: turn a shape object into an SVG string
function shapeToSvg(shape) {
  if (shape.type === 'rect') {
    const {x, y, width, height, fill = 'lightgray'} = shape;
    return `<rect x="${x}" y="${y}" width="${width}" height="${height}" fill="${fill}" stroke="black"/>`;
  }
  if (shape.type === 'arrow') {
    const {x1, y1, x2, y2, color = 'black'} = shape;
    return `<line x1="${x1}" y1="${y1}" x2="${x2}" y2="${y2}" stroke="${color}" marker-end="url(#arrowhead)"/>`;
  }
  return '';
}

// Route: render diagram as a self‑contained HTML page
app.get('/view/:id', (req, res) => {
  const id = req.params.id;
  db.get('SELECT json FROM diagrams WHERE id = ?', [id], (err, row) => {
    if (err) return res.status(500).send('DB error');
    if (!row) return res.status(404).send('Diagram not found');
    let diagram;
    try { diagram = JSON.parse(row.json); } catch { return res.status(400).send('Invalid JSON'); }
    const svgContent = diagram.shapes.map(shapeToSvg).join('\n');
    const html = `<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Diagram ${id}</title></head>
<body>
<svg width="${diagram.width || 800}" height="${diagram.height || 600}" xmlns="http://www.w3.org/2000/svg">
  <defs>
    <marker id="arrowhead" markerWidth="10" markerHeight="7" refX="10" refY="3.5" orient="auto">
      <polygon points="0 0, 10 3.5, 0 7" fill="black" />
    </marker>
  </defs>
  ${svgContent}
</svg>
</body>
</html>`;
    res.send(html);
  });
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => console.log(`Server listening on http://localhost:${PORT}`));

Phase 4: Seed a Sample Diagram & Run

Now we put a tiny diagram into the SQLite store so the server has something to render. Using the sqlite3 CLI we insert a single row with JSON that describes a rectangle and an arrow pointing to it. After the insert we launch the Node server; it will immediately be able to serve the new diagram at /view/1.

The sample JSON mirrors the shape types our builder understands, keeping the clone lightweight yet functional.

# Ensure the data folder exists
mkdir -p data
# Create the DB and table if they don't exist
sqlite3 data/diagrams.db "CREATE TABLE IF NOT EXISTS diagrams (id INTEGER PRIMARY KEY AUTOINCREMENT, json TEXT NOT NULL);"
# Insert a simple diagram (id will be 1)
sqlite3 data/diagrams.db <<'SQL'
INSERT INTO diagrams (json) VALUES ('{"width":600,"height":400,"shapes":[{"type":"rect","x":100,"y":150,"width":200,"height":100,"fill":"lightblue"},{"type":"arrow","x1":50,"y1":200,"x2":100,"y2":200,"color":"red"}]}');
SQL
# Start the server
node src/server.js

Phase 5: Verify & Extend

With the server running, a quick curl confirms the endpoint returns a full HTML page containing an <svg> element. Open the URL in a browser to see a light‑blue rectangle and a red arrow – proof that our JSON‑to‑SVG pipeline works. From here you can easily add new shape handlers (e.g., circles, text) or sprinkle CSS into the generated HTML to style the viewer further.

# Verify the HTML contains an <svg> tag
curl -s http://localhost:3000/view/1 | grep -i '<svg'
