Simple Agentic Skills Framework in Shell (Clone of Superpowers)

A minimal, 45‑minute clone using Bash and SQLite

Welcome to another official UVF IT guide! In this quick build you’ll create a tiny agentic‑skills framework that runs entirely in your terminal, inspired by the Superpowers project. We’ll wire up a Bash script that stores skill definitions in SQLite and lets you invoke them with simple commands.

We’ll keep the stack ultra‑light: Bash for the runtime, SQLite (bundled with most OSes) for persistence, and no external APIs. In ~45 minutes you’ll have a working prototype you can extend with your own skills.

Before you start

  • You need Bash 4+ and SQLite 3 installed (most Linux/macOS machines have them out‑of‑the‑box).
  • The clone only supports plain‑text skills and a single‑user workflow – the real Superpowers platform includes multi‑agent orchestration and cloud AI services which are omitted here.
Architecture Overview
1

Phase 1: Scaffold project

Create a directory and initialise an empty SQLite database with a simple schema. This gives us a predictable place to store skill metadata and a clean starting point for the rest of the guide.

The script is idempotent – you can run it again without harming existing data, which is handy while you experiment.

init.sh

#!/usr/bin/env bash
set -euo pipefail

# Project root (relative to script location)
PROJECT_ROOT="$(dirname "${BASH_SOURCE[0]}")/superpowers_clone"

# Create folder if it doesn't exist
mkdir -p "$PROJECT_ROOT"

# Path to the SQLite DB file
DB_PATH="$PROJECT_ROOT/skills.db"

# Initialise DB with a simple schema if not present
if ! sqlite3 "$DB_PATH" "SELECT name FROM sqlite_master WHERE type='table' AND name='skills';" | grep -q skills; then
  sqlite3 "$DB_PATH" <<SQL
CREATE TABLE skills (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  description TEXT,
  command TEXT NOT NULL
);
SQL
  echo "Database initialized at $DB_PATH"
else
  echo "Database already exists – schema is present."
fi
2

Phase 2: Core feature – Add a skill

A helper script inserts a new skill record into the DB. Each skill is a name, a short description, and the shell command that implements it – the minimal equivalent of Superpowers' skill objects.

Running the script with arguments adds the skill, and you can later query the DB to see what you stored.

add_skill.sh

#!/usr/bin/env bash
set -euo pipefail

if [[ $# -lt 3 ]]; then
  echo "Usage: $0 <skill_name> <description> <command>"
  exit 1
fi

SKILL_NAME="$1"
DESCRIPTION="$2"
COMMAND="$3"

# Locate the DB (same folder as init.sh)
SCRIPT_DIR="$(dirname "${BASH_SOURCE[0]}")"
DB_PATH="$SCRIPT_DIR/superpowers_clone/skills.db"

# Insert the new skill – ignore if it already exists
sqlite3 "$DB_PATH" <<SQL
INSERT OR IGNORE INTO skills (name, description, command)
VALUES ('$SKILL_NAME', '$DESCRIPTION', '$COMMAND');
SQL

echo "Skill '$SKILL_NAME' added (or already existed)."
3

Phase 3: Core feature – List & run skills

We now add a tiny helper that reads the SQLite catalog and prints every registered skill. The script shows the skill ID, name, and a short description so users can pick what to run. It uses the same sqlite3 binary we relied on earlier, keeping the whole stack pure Bash.

Next we create a companion script that will later execute a chosen skill. By separating listing from execution we keep each utility focused and easy to test, which is perfect for a minimal clone.

list_skills.sh

#!/usr/bin/env bash
# list_skills.sh – display all registered skills
DB_DIR="superpowers_clone"
DB_PATH="$DB_DIR/skills.db"
if [[ ! -f $DB_PATH ]]; then
  echo "Database not found at $DB_PATH"
  exit 1
fi
printf "%4s | %-15s | %s\n" "ID" "NAME" "DESCRIPTION"
printf "----+-----------------+---------------------------\n"
sqlite3 "$DB_PATH" "SELECT id, name, description FROM skill ORDER BY id;" |
while IFS='|' read -r id name desc; do
  printf "%4s | %-15s | %s\n" "$id" "$name" "$desc"
done
4

Phase 4: Run a skill

The runner script receives a skill ID, looks up the stored command, and executes it in a controlled subshell. We deliberately avoid eval on raw input; instead we pass the command string to bash -c which respects quoting and reduces injection risk.

After the command runs we echo a separator line so the user can clearly see the skill output. This tiny utility completes the core loop: list → pick → run, giving you a functional agentic‑skills framework in pure Bash.

run_skill.sh

#!/usr/bin/env bash
# run_skill.sh – fetch and execute a skill by its ID
DB_DIR="superpowers_clone"
DB_PATH="$DB_DIR/skills.db"
if [[ -z $1 ]]; then
  echo "Usage: $0 <skill_id>"
  exit 1
fi
SKILL_ID="$1"
if [[ ! -f $DB_PATH ]]; then
  echo "Database not found at $DB_PATH"
  exit 1
fi
# Retrieve the command for the given ID
CMD=$(sqlite3 "$DB_PATH" "SELECT command FROM skill WHERE id=$SKILL_ID;")
if [[ -z $CMD ]]; then
  echo "No skill found with ID $SKILL_ID"
  exit 1
fi
echo "--- Executing skill #$SKILL_ID ---"
# Execute in a subshell to isolate environment
bash -c "$CMD"
echo "--- Done ---"
