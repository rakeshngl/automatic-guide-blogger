Turn Any Work into an API – Mini‑Tool

A tiny Flask‑SQLite clone of Periscope

Welcome to another official UVF IT guide! In the next 45 minutes you’ll spin up a minimal web service that turns arbitrary spreadsheet‑like data into a simple REST API – the core idea behind Periscope.

We’ll use Python 3, Flask, and SQLite – all free, no external keys required. By the end you’ll have a local server you can query with curl or a browser, and a clear path to add authentication or richer queries.

Before you start…

  • You need Python 3.9+ and pip installed; the guide assumes a Unix‑like shell (Linux/macOS or WSL).
  • The clone only supports a single table called items; the real Periscope lets you upload CSVs, define multiple endpoints, and add auth – those are omitted for brevity.

Phase 1: Scaffold the project

Create a fresh folder for the project, spin up a virtual environment, and install Flask. This isolates your dependencies so the clone won’t clash with other Python work on your machine.

We’ll also generate a basic requirements.txt so you can reinstall later or share the project with a teammate. All of this is done from the command line, keeping the setup reproducible.

Phase 2: Define the data model (SQLite)

We need a tiny SQLite database that stores rows for an items table. The table will have an auto‑incrementing id, a name column, and a value column – enough to demonstrate CRUD later.

The following script creates data.db, defines the schema, and seeds it with two example rows so the API has something to return right away.

init_db.py

import sqlite3

conn = sqlite3.connect('data.db')
cur = conn.cursor()

# Create the items table
cur.execute('''
CREATE TABLE IF NOT EXISTS items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    value TEXT NOT NULL
);
''')

# Seed with two rows
cur.executemany('INSERT INTO items (name, value) VALUES (?, ?)', [
    ('alpha', 'first'),
    ('beta', 'second')
])

conn.commit()
conn.close()
print('Database initialized with 2 items.')

Phase 3: Build the API endpoint

In this step we expose the data stored in SQLite through a simple HTTP GET endpoint. The route /api/items will query all rows from the items table and serialize them as JSON, making the database consumable by any client. Keeping the logic tiny helps you see exactly how Flask talks to SQLite and returns a response.

We use the sqlite3 module to open a connection each request, fetch the rows, and then convert the list of tuples into dictionaries that Flask's jsonify can turn into proper JSON. This keeps the code stateless and easy to extend later with POST or PUT routes.

app.py

from flask import Flask, jsonify, g
import sqlite3

app = Flask(__name__)
DB_PATH = 'data.db'

def get_db():
    if 'db' not in g:
        g.db = sqlite3.connect(DB_PATH)
        g.db.row_factory = sqlite3.Row
    return g.db

@app.teardown_appcontext
def close_db(exc):
    db = g.pop('db', None)
    if db is not None:
        db.close()

@app.route('/api/items', methods=['GET'])
def get_items():
    cur = get_db().execute('SELECT id, name, value FROM items')
    rows = cur.fetchall()
    cur.close()
    items = [dict(row) for row in rows]
    return jsonify(items)

if __name__ == '__main__':
    app.run(debug=True)
4

Phase 4: Run locally

Now that the Flask app is ready, start it from the command line. Flask’s built‑in development server will bind to 127.0.0.1:5000 by default, which you can reach in a browser or with curl. Running in debug mode gives you live reloads as you tweak the code, perfect for a quick prototype.

Make sure you are in the same directory as app.py and that the data.db file created by the initializer exists before launching.

python app.py
5

Phase 5: Verify and extend

With the server up, verify the endpoint returns the expected JSON payload. A simple curl request (or opening the URL in a browser) should display an array of objects, each representing a row from the items table. Once the GET works, you can start adding more routes—like POST to insert new items—or swap SQLite for a more robust database such as Postgres.

The goal here is to prove the clone behaves like a minimal Periscope API and to give you a launchpad for further experimentation.

curl http://127.0.0.1:5000/api/items
