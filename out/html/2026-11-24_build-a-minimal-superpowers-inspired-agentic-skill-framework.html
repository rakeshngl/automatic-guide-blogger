Build a Minimal Superpowers‑Inspired Agentic Skill Framework

A 45‑minute beginner’s clone using Python and SQLite

Welcome to another official UVF IT build guide! In this tutorial you’ll create a tiny, working version of the Superpowers agentic skill framework – a lightweight system that lets a simple Python “agent” load, execute, and chain tiny “skills” stored in a SQLite database.

We’ll use only free‑tier tools (Python 3.11, SQLite, and Flask for a tiny UI) so you can finish the whole thing in under an hour and then experiment further.

Before you start

  • You need Python 3.10+ and pip installed – older versions may miss sqlite3 improvements.
  • The real Superpowers project ships dozens of skills and a sophisticated orchestration engine; this clone only supports a single‑step skill lookup and execution.

Phase 2: Define the skill model (SQLite)

Now we set up a minimal SQLite database that will store our skills. The table skills holds an auto‑increment id, a human‑readable name, and a code column that contains a raw Python function body as text – this mimics the way Superpowers stores executable snippets.

The helper script init_db.py creates the database file, builds the table, and seeds it with a single example skill called "greet". Running the script will give you a ready‑to‑query skills.db that the Flask API can later read from.

init_db.py

import sqlite3

DB_PATH = 'skills.db'

def init_db():
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    # Create the skills table
    cur.execute('''
        CREATE TABLE IF NOT EXISTS skills (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            name TEXT NOT NULL UNIQUE,
            code TEXT NOT NULL
        )
    ''')
    # Seed with a simple greeting skill
    greet_code = "def run():\n    return 'Hello from the greet skill!'"
    cur.execute('INSERT OR REPLACE INTO skills (name, code) VALUES (?, ?)', ('greet', greet_code))
    conn.commit()
    conn.close()

if __name__ == '__main__':
    init_db()
    print('Database initialized with sample skill.')

Phase 3: Build the API & UI

In this step we spin up a tiny Flask server that talks to the SQLite skill store we created earlier. The root route (/) renders a minimal HTML form so you can pick a skill name and supply an argument, while the /run endpoint receives the form data, looks up the Python snippet, executes it safely, and returns the result as JSON. Keeping the UI tiny lets you focus on the core idea: a skill is just a row in the DB that contains executable code.

We deliberately avoid heavy templating or authentication – the goal is a clear, readable example you can run in minutes. The Flask app also handles basic error cases, such as a missing skill or a runtime exception, and reports them back to the UI so you can see what went wrong without digging into logs.

app.py

import sqlite3, json, traceback
from flask import Flask, request, jsonify, render_template_string

app = Flask(__name__)
DB_PATH = 'skills.db'

HTML_FORM = '''
<!doctype html>
<title>Skill Runner</title>
<h2>Run a Skill</h2>
<form action="/run" method="post">
  Skill name: <input name="name" placeholder="echo"><br>
  Argument: <input name="arg" placeholder="hello"><br>
  <input type="submit" value="Run">
</form>
{% if result %}<h3>Result</h3><pre>{{ result }}</pre>{% endif %}
''' 

def get_skill_code(name):
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    cur.execute('SELECT code FROM skills WHERE name=?', (name,))
    row = cur.fetchone()
    conn.close()
    return row[0] if row else None

def exec_skill(code, arg):
    # Very limited sandbox: only expose `arg` and capture `result`
    local_vars = {'arg': arg, 'result': None}
    try:
        exec(code, {}, local_vars)
        return local_vars.get('result')
    except Exception:
        return {'error': traceback.format_exc()}

@app.route('/', methods=['GET'])
def index():
    return render_template_string(HTML_FORM)

@app.route('/run', methods=['POST'])
def run_skill():
    name = request.form.get('name')
    arg = request.form.get('arg')
    code = get_skill_code(name)
    if not code:
        return jsonify({'error': f'Skill "{name}" not found'}), 404
    outcome = exec_skill(code, arg)
    if isinstance(outcome, dict) and 'error' in outcome:
        return jsonify(outcome), 500
    return jsonify({'result': outcome})

if __name__ == '__main__':
    app.run(debug=True)

Phase 4: Run locally

Now that the Flask app is ready, we first make sure the SQLite database is seeded with at least one skill (the echo skill). Then we launch the server with a single command. When the server starts, open your browser to http://localhost:5000 – you’ll see the tiny form we defined earlier. Submit echo as the skill name and any text as the argument; the page will display the JSON result returned by the API.

If you prefer the command line, you can also POST directly with curl. This phase shows both interactive UI usage and a quick CLI test, confirming the whole stack – DB, Flask, and execution logic – works together.

# Seed the database (run once)
python - <<'PY'
import sqlite3, json
conn = sqlite3.connect('skills.db')
cur = conn.cursor()
cur.execute('CREATE TABLE IF NOT EXISTS skills (name TEXT PRIMARY KEY, code TEXT)')
# Simple echo skill: returns "Echo: <arg>"
code = "result = f'Echo: {arg}'"
cur.execute('INSERT OR REPLACE INTO skills (name, code) VALUES (?,?)', ('echo', code))
conn.commit()
conn.close()
PY

# Start the Flask server
export FLASK_APP=app.py
flask run

Phase 5: Verify and extend

With the server running, verify the endpoint works either via the browser form or a curl call. You should receive a JSON payload like {"result":"Echo: your text"}. This confirms the skill was fetched from SQLite, executed, and serialized back to the client.

To grow the framework, simply add more rows to the skills table. Each row stores a Python snippet that can use the provided arg variable and must assign its output to result. Experiment by adding a reverse skill that returns the reversed string, or a len skill that returns the length of the argument. No code changes are needed – the API automatically picks up new skills.

# Quick test with curl
curl -X POST -d "name=echo&arg=hello world" http://localhost:5000/run

# Add a new skill (reverse) directly via sqlite3
sqlite3 skills.db "INSERT OR REPLACE INTO skills (name, code) VALUES ('reverse', 'result = arg[::-1]');"
# Test the new skill
curl -X POST -d "name=reverse&arg=hello" http://localhost:5000/run
