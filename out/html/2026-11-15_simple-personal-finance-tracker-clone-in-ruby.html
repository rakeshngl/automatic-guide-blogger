Simple Personal Finance Tracker Clone in Ruby

A beginner-friendly clone of Sure using Sinatra and SQLite

Welcome to another official UVF IT guide! In this quick‑fire tutorial we’ll build a tiny personal finance tracker inspired by Sure, using only free, open‑source tools you can run on your laptop.

In about 45 minutes you’ll have a working web app that lets you add transactions and view a running balance – perfect for learning Ruby web development without any paid services.

Before You Start

  • You need Ruby 3.1+ and the bundler gem installed; older versions may cause syntax errors.
  • The real Sure app includes AI assistants, multi‑currency support, and charts – our clone skips those for simplicity.

Phase 1: Scaffold the Project

First we create a clean folder for our clone and tell Ruby's package manager Bundler to manage dependencies. This gives us an isolated environment so the gems we install won’t clash with other projects on your machine.

Next we add the Sinatra web framework and the SQLite3 driver to the Gemfile. Bundler will fetch the correct versions and lock them, making the setup reproducible for anyone who follows the guide.

setup.sh

#!/usr/bin/env bash
set -e
# Create project directory
mkdir -p finance_tracker && cd finance_tracker
# Initialise Bundler and create a Gemfile
bundle init > /dev/null
# Add required gems
cat <<'GEMS' >> Gemfile
gem 'sinatra', '~> 2.2'
gem 'sqlite3', '~> 1.6'
GEMS
# Install gems
bundle install
# Create a basic app file
cat <<'RUBY' > app.rb
require 'sinatra'
require 'sqlite3'
set :bind, '0.0.0.0'
RUBY
echo "Scaffold complete. Run 'ruby app.rb' after initializing the database."
2

Phase 2: Define the Data Model

Now we set up a tiny SQLite database that will store each financial transaction. A single table called transactions is enough for a basic tracker – it holds an amount, a description, and a timestamp.

The script below creates the finance.db file (if it doesn’t exist) and ensures the table schema is present. Running it once is all you need before starting the web server.

init_db.sh

#!/usr/bin/env bash
set -e
DB_FILE=finance.db
# Create database and transactions table if they don't exist
sqlite3 $DB_FILE <<'SQL'
CREATE TABLE IF NOT EXISTS transactions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  amount REAL NOT NULL,
  description TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
SQL
echo "Database initialized at $DB_FILE with 'transactions' table."
3

Phase 3: Build the API & UI

In this phase we create a single Sinatra application that serves both the HTML UI and the backend logic. The UI consists of a simple form for entering a transaction (date, description, amount) and a table that lists all stored transactions with a running balance. We use SQLite3 for persistence, which was set up in the scaffolding phase, and we keep the code tiny so beginners can follow each line.

We expose three routes: GET / renders the form and the table, POST /transactions saves a new entry, and a helper method calculates the current balance. All HTML is embedded directly in Ruby strings to avoid extra template files, keeping the clone self‑contained.

app.rb

require 'sinatra'
require 'sqlite3'
require 'json'

DB = SQLite3::Database.new('finance.db')
DB.results_as_hash = true

# Ensure the transactions table exists
DB.execute <<-SQL
  CREATE TABLE IF NOT EXISTS transactions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    date TEXT NOT NULL,
    description TEXT NOT NULL,
    amount REAL NOT NULL
  );
SQL

helpers do
  def all_transactions
    DB.execute('SELECT * FROM transactions ORDER BY date DESC')
  end

  def current_balance
    DB.execute('SELECT SUM(amount) FROM transactions').first[0] || 0.0
  end
end

get '/' do
  @transactions = all_transactions
  @balance = current_balance
  erb :index
end

post '/transactions' do
  DB.execute('INSERT INTO transactions (date, description, amount) VALUES (?, ?, ?)',
             params['date'], params['description'], params['amount'].to_f)
  redirect '/'
end

__END__

Phase 4: Run Locally

Now we start the Sinatra server so you can interact with the tracker in your browser. The helper script sets the appropriate environment variables and launches the app on the default port 4567. Running it from the command line gives you live reloads on code changes, which is handy while you experiment.

Make sure you have the sinatra gem installed (it was added in the scaffold phase). If you see the familiar "Sinatra has taken the stage" message, the server is ready for you to open http://localhost:4567.

run.sh

#!/usr/bin/env bash
# Ensure bundler uses the local Gemfile
export BUNDLE_GEMFILE=$(pwd)/Gemfile
# Install missing gems quietly
bundle check || bundle install --quiet
# Start the Sinatra app
ruby app.rb -o 0.0.0.0 -p 4567
5

Phase 5: Verify & Extend

With the server running, open your browser to http://localhost:4567. You should see the empty form and a table with no rows, plus a balance of $0.00. Add a transaction using the form; after submission the page reloads, showing the new row and an updated balance – that confirms the API and UI are wired correctly.

As a next step, you can export all transactions to a CSV file. The optional script below queries the SQLite database and writes a simple CSV, giving you a foundation for reporting or backups. Feel free to tweak the UI, add categories, or integrate Chart.js for visual balance trends.

export.sh

#!/usr/bin/env bash
# Export all transactions to finance.csv in the current directory
sqlite3 finance.db -header -csv "SELECT date, description, amount FROM transactions ORDER BY date;" > finance.csv
if [ -s finance.csv ]; then
  echo "Exported $(wc -l < finance.csv) lines to finance.csv"
else
  echo "No data exported; the table may be empty."
fi
