Mini Uptime‑Kuma Monitoring Dashboard

A lightweight Node.js + SQLite clone you can build in 45 minutes

Welcome to another official UVF IT build guide! In this tutorial we’ll create a tiny monitoring dashboard inspired by Uptime‑Kuma, using only Node.js, Express, and SQLite – all free on your own machine.

You’ll get a simple web UI to add URLs, store them in a local SQLite DB, and poll them every 20 seconds to show up/down status – a perfect starter project for any beginner dev.

Before you start…

  • Node.js >= 18 and npm must be installed; older versions may lack native fetch support.
  • We replace the full‑featured UI with a minimal HTML page – no React, no dark mode, no multi‑language support.
  • The clone only checks HTTP GET responses (status 200 = up); real Uptime‑Kuma supports many protocols and advanced alerts.
Mini Uptime‑Kuma Architecture
1

Phase 1: Scaffold the project

Create a fresh npm project and install the tiny dependencies we need. This gives us a clean folder, a package.json to track scripts, and the two libraries—Express for the web server and better‑sqlite3 for fast, synchronous SQLite access.

All commands are run from your terminal inside the project folder. After this step you’ll have a ready‑to‑code environment.

mkdir mini-uptime-kuma && cd $_
npm init -y
npm install express better-sqlite3
# optional: add a start script for convenience
npm set-script start "node index.js"
2

Phase 2: Define the data model

Set up SQLite with a single table to store monitored URLs and their last status. We keep the schema tiny: an auto‑increment id, the URL string, the last HTTP status code, and a timestamp of the last check.

The file db.js will be required by the server and any future workers. It opens (or creates) monitor.db in the project root and ensures the table exists before anything else runs.

db.js

const Database = require('better-sqlite3');
// Open (or create) the SQLite file in the current directory
const db = new Database('monitor.db');

// Create the table if it doesn't exist yet
const createTable = `
CREATE TABLE IF NOT EXISTS monitors (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  url TEXT NOT NULL,
  last_status INTEGER,
  last_checked INTEGER
);
`;
db.exec(createTable);

module.exports = db;
3

Phase 3: Build API & UI routes

In this step we wire up an Express server that talks to a SQLite database. We'll create three endpoints: one to fetch all monitored sites, one to add a new site, and a simple HTML page that displays each site's URL and its current status. The UI is deliberately tiny – just a form and a table – so you can see the data flow without getting lost in styling.

We keep the server logic in a single file (server.js) so the project stays easy to follow. Every route uses parameterized SQL statements to avoid injection, and the HTML page pulls the JSON list via a <script> tag, rendering it with plain JavaScript.

server.js

const express = require('express');
const sqlite3 = require('sqlite3').verbose();
const path = require('path');

const app = express();
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// Initialise SQLite DB and table
const db = new sqlite3.Database('./data.db');
db.run(`CREATE TABLE IF NOT EXISTS sites (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  url TEXT NOT NULL,
  status TEXT DEFAULT 'unknown'
)`);

// API: list all sites
app.get('/api/sites', (req, res) => {
  db.all('SELECT * FROM sites', [], (err, rows) => {
    if (err) return res.status(500).json({error: err.message});
    res.json(rows);
  });
});

// API: add a new site
app.post('/api/sites', (req, res) => {
  const { url } = req.body;
  if (!url) return res.status(400).json({error: 'url required'});
  db.run('INSERT INTO sites (url) VALUES (?)', [url], function(err) {
    if (err) return res.status(500).json({error: err.message});
    res.json({id: this.lastID, url, status: 'unknown'});
  });
});

// UI: tiny dashboard
app.get('/', (req, res) => {
  res.sendFile(path.join(__dirname, 'index.html'));
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => console.log(`🚀 http://localhost:${PORT}`));
4

Phase 4: Add the polling worker

Now we need a background process that checks each stored URL every 20 seconds and writes the result back to SQLite. The worker runs as a separate Node script (poller.js) so it can keep looping without blocking the HTTP server.

We use the native fetch API (available in Node 18+) to request each site. If the request succeeds (status < 400) we mark the site as up; otherwise we store down. The worker logs its activity so you can see it working in the terminal.

poller.js

const sqlite3 = require('sqlite3').verbose();
const db = new sqlite3.Database('./data.db');
const fetch = (...args) => import('node-fetch').then(({default: fetch}) => fetch(...args));

const INTERVAL_MS = 20_000;

function pollSite(site) {
  return fetch(site.url, {method: 'HEAD', timeout: 5000})
    .then(res => (res.ok ? 'up' : 'down'))
    .catch(() => 'down');
}

function runPoller() {
  db.all('SELECT id, url FROM sites', [], async (err, rows) => {
    if (err) return console.error('DB error:', err);
    for (const site of rows) {
      const status = await pollSite(site);
      db.run('UPDATE sites SET status = ? WHERE id = ?', [status, site.id]);
      console.log(`${new Date().toISOString()} - ${site.url} is ${status}`);
    }
  });
}

setInterval(runPoller, INTERVAL_MS);
// Immediate first run
runPoller();
5

Phase 5: Run locally and verify

With the server and poller ready, start both processes. The server listens on port 3000 and serves the dashboard; the poller runs in the background, updating statuses every 20 seconds.

Open http://localhost:3000 in a browser, add a URL via the form, and watch the table refresh (you can hit the refresh button). After a short wait the status column will change to “up” or “down” based on the poller’s latest check.

# Install dependencies (run once)
npm install express sqlite3 node-fetch

# In one terminal, start the API/UI server
node server.js &

# In another terminal, start the polling worker
node poller.js

# Now open your browser:
#   http://localhost:3000
