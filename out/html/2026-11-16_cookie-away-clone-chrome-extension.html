Cookie‑Away Clone Chrome Extension

Reject cookie banners automatically

Welcome to another official UVF IT guide where we build a tiny Chrome extension that dismisses cookie consent banners – a minimal clone of Cookie Away. You’ll get a working blocker in under an hour using only HTML, CSS, and JavaScript, no paid services required.

We’ll scaffold the extension, add a simple rule‑based detector, wire it to Chrome’s content‑script API, run it locally, and verify it blocks a typical banner. Feel free to extend the rule list later!

Before you start

  • You need Node ≥ 14 or any recent Python install only for optional tooling – the extension itself runs purely in the browser.
  • The clone only handles obvious banner patterns (fixed‑position divs with keywords); it won’t defeat sophisticated consent managers.
  • Make sure Chrome’s “Developer mode” is enabled when loading the unpacked extension.
Extension Architecture
1

Phase 1: Scaffold the extension

Create a new folder for the extension and place a manifest.json file inside. The manifest tells Chrome which scripts to run, what permissions are needed, and provides basic metadata like the name and version. Keeping it minimal helps you focus on the core logic without extra baggage.

manifest.json

{
  "manifest_version": 3,
  "name": "Cookie‑Away Clone",
  "version": "1.0",
  "description": "Automatically hides cookie consent banners.",
  "permissions": ["scripting", "storage"],
  "host_permissions": ["<all_urls>"],
  "action": {
    "default_popup": "popup.html",
    "default_icon": {
      "16": "icons/icon16.png",
      "48": "icons/icon48.png",
      "128": "icons/icon128.png"
    }
  },
  "content_scripts": [
    {
      "matches": ["<all_urls>"],
      "js": ["contentScript.js"],
      "run_at": "document_idle"
    }
  ]
}

Phase 2: Core detection logic (model)

We add a tiny rule‑based detector that scans the page for elements containing common cookie‑banner keywords. When a match is found, the script removes the element from the DOM, effectively hiding the banner. This approach is lightweight and runs entirely in the content script, so no background processing is needed.

contentScript.js

// List of keywords that commonly appear in cookie banners
const KEYWORDS = [
  'cookie',
  'consent',
  'privacy',
  'accept',
  'reject',
  'gdpr'
];

// Helper: does element's text contain any keyword?
function containsKeyword(text) {
  const lower = text.toLowerCase();
  return KEYWORDS.some(k => lower.includes(k));
}

// Scan visible elements and remove those that look like a banner
function removeBanners() {
  const candidates = document.querySelectorAll('div,section,footer');
  candidates.forEach(el => {
    if (el.offsetParent !== null && containsKeyword(el.innerText)) {
      const style = getComputedStyle(el);
      if (style.position === 'fixed' || style.position === 'sticky') {
        el.remove();
        console.log('Cookie‑Away Clone: removed banner', el);
      }
    }
  });
}

// Run once on load, then observe for dynamic banners
removeBanners();
const observer = new MutationObserver(removeBanners);
observer.observe(document.body, { childList: true, subtree: true });

Phase 3: Simple UI to toggle the blocker

In this step we create a tiny popup that appears when the user clicks the extension icon. The popup contains a single checkbox that reflects whether the blocker is active, letting users turn it on or off without digging into Chrome's settings. We’ll store the state in Chrome's synchronized storage so it persists across browser restarts.

The HTML is deliberately minimal – a heading, a label with a checkbox, and a small script tag that loads our popup logic. This keeps the UI lightweight and fast to load each time the user opens the popup.

popup.html

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Cookie‑Away Toggle</title>
  <style>
    body {font-family:Arial,sans-serif;margin:10px;}
    label {cursor:pointer;}
  </style>
</head>
<body>
  <h3>Cookie‑Away</h3>
  <label>
    <input type="checkbox" id="blockerToggle"> Enable blocker
  </label>
  <script src="popup.js"></script>
</body>
</html>
4

Phase 4: Popup script to persist toggle

Now we wire the checkbox to Chrome's storage API. When the popup loads we read the saved preference and set the checkbox accordingly. Any change the user makes is saved immediately and a message is broadcast to all content scripts so they can react in real time.

Using chrome.runtime.sendMessage keeps the communication simple: the content script listens for a toggle action and updates its internal flag without needing to reload the page.

popup.js

// popup.js – runs in the popup context
const toggle = document.getElementById('blockerToggle');

// Load saved state
chrome.storage.sync.get({enabled:true}, (data) => {
  toggle.checked = data.enabled;
});

// Save state on change and notify content scripts
toggle.addEventListener('change', () => {
  const enabled = toggle.checked;
  chrome.storage.sync.set({enabled}, () => {
    // Broadcast to all tabs
    chrome.tabs.query({url: '<all_urls>'}, (tabs) => {
      tabs.forEach(tab => {
        chrome.tabs.sendMessage(tab.id, {action:'toggle', enabled});
      });
    });
  });
});
5

Phase 5: Run locally & verify

With the UI and persistence in place, it’s time to load the extension into Chrome and see it work. Open the extensions page, enable Developer mode, and load the folder containing manifest.json, content.js, popup.html, and popup.js. Then visit a site that shows a cookie consent banner to confirm the blocker removes it automatically.

Try toggling the checkbox in the popup; the banner should reappear when you disable the blocker and disappear again when you re‑enable it. This confirms the communication loop between the popup, storage, and content script is solid.
