PyTorch Model Visualizer Clone

A minimal web app to inspect PyTorch model layers

Welcome to another official UVF IT guide. In the next 45 minutes you’ll spin up a tiny web‑based visualizer that mirrors the core idea of tensorViz – showing the inner structure of a PyTorch model without any paid services.

We’ll use Python, Flask, and plain HTML, store nothing in a database, and keep the code under 100 lines total – perfect for a beginner looking to understand model introspection.

Before you start

  • You need Python 3.9+ and pip installed; older versions may miss torch wheels.
  • The clone only lists layer names and types – no interactive graph or weight visualizations that the real product offers.
  • Running on Windows may require the Visual C++ Build Tools for the torch wheel; Linux/macOS are smoother.

Phase 2: Define a simple model (core data)

We’ll use a tiny CNN so the visualizer has something to show.

model.py

import torch
import torch.nn as nn

class TinyCNN(nn.Module):
    def __init__(self):
        super(TinyCNN, self).__init__()
        self.conv1 = nn.Conv2d(1, 8, kernel_size=3, stride=1, padding=1)
        self.relu = nn.ReLU()
        self.pool = nn.MaxPool2d(2, 2)
        self.fc = nn.Linear(8 * 14 * 14, 10)  # assuming 28x28 input

    def forward(self, x):
        x = self.pool(self.relu(self.conv1(x)))
        x = x.view(x.size(0), -1)
        x = self.fc(x)
        return x

# Instantiate for later import
model = TinyCNN()
print("Model layers:")
for name, layer in model.named_children():
    print(f"{name}: {layer.__class__.__name__}")

Phase 3: Build the Flask API & UI

We’ll spin up a tiny Flask server that loads a simple PyTorch model and exposes its architecture via an endpoint. The /layers route will walk through the model’s named modules and return a JSON array of objects containing each layer’s name and type. The root route (/) will serve a minimal HTML page that fetches this JSON and renders the layer list as <li> items, giving you a live view of the model structure.

The UI is intentionally tiny: a single <ul> element that gets populated by JavaScript once the data arrives. This keeps the clone lightweight while still demonstrating the core idea of visualising model layers in the browser.

app.py

import json
from flask import Flask, jsonify, render_template_string
import torch.nn as nn

app = Flask(__name__)

# Simple example model – replace with any loaded .pt model later
model = nn.Sequential(
    nn.Conv2d(3, 16, kernel_size=3, stride=1, padding=1),
    nn.ReLU(),
    nn.MaxPool2d(2),
    nn.Flatten(),
    nn.Linear(16 * 16 * 16, 10),
    nn.Softmax(dim=1)
)

@app.route('/')
def index():
    # Inline HTML for brevity; in a real app use templates/static files
    html = """
    <!doctype html>
    <html lang='en'>
    <head><meta charset='utf-8'><title>Model Layers</title></head>
    <body>
      <h1>Model Layers</h1>
      <ul id='layer-list'></ul>
      <script>
        fetch('/layers')
          .then(r => r.json())
          .then(data => {
            const ul = document.getElementById('layer-list');
            data.forEach(l => {
              const li = document.createElement('li');
              li.textContent = `${l.name}: ${l.type}`;
              ul.appendChild(li);
            });
          });
      </script>
    </body>
    </html>
    """
    return render_template_string(html)

@app.route('/layers')
def layers():
    layer_info = []
    for name, module in model.named_modules():
        # Skip the top-level container itself
        if name == "":
            continue
        layer_info.append({"name": name, "type": module.__class__.__name__})
    return jsonify(layer_info)

if __name__ == '__main__':
    app.run(debug=True)

Phase 4: Run locally

Now that the Flask app is ready, start the development server with a single command. The server will listen on http://127.0.0.1:5000 by default, and you can open that URL in any browser to see the UI rendering the layer list.

If you make changes to app.py, simply stop the process (Ctrl‑C) and rerun the command – Flask’s debug mode will also reload automatically on file changes.

python app.py

Phase 5: Verify & extend

Confirm the clone works by visiting the root page and checking that each layer appears as a list item. You can also hit the /layers endpoint directly with curl to see the raw JSON payload, which is useful for debugging or integration with other tools.

As an optional next step, you could add a file‑upload form that accepts a .pt checkpoint, loads it with torch.load, and replaces the example model on the fly. This turns the minimal clone into a flexible visualizer for any PyTorch model you own.
