Tiny Agentic Skills Demo with Superpowers

A beginner-friendly clone of a coding‑agent workflow using the open‑source Superpowers framework

Welcome to another official UVF IT build guide! In the next 45 minutes you’ll spin up a minimal agentic skills demo that mimics the core loop of the Superpowers framework – spec‑gather, plan, and generate code – all running locally with Python and SQLite.

We’ll use the free‑tier Superpowers package, a tiny Flask API, and a SQLite DB to store skill definitions. No paid APIs, no cloud services – just pure open‑source code you can run on any modern laptop.

Prerequisites & Gotchas

  • You need Python 3.10+ and git installed; older versions may miss type‑hint features used in the demo.
  • The real Superpowers framework ships dozens of skills; this clone implements only a single "echo" skill to keep things simple.
  • Running the Flask server on port 5000 may conflict with other local services – stop any existing process or change the port in app.py.

Next we activate the environment and pull in the only two libraries we need – Flask for the HTTP API and SQLAlchemy to talk to SQLite. With everything installed we’re ready to write code.

2

Phase 2: Define the skill model (SQLite)

We now create a tiny SQLAlchemy model that mirrors Superpowers’ skill registry. Each row stores a human‑readable name and a Python code snippet that the agent can execute later.

The model lives in models.py and will be imported by the Flask app to read and write skill definitions in a local SQLite file.

models.py

from sqlalchemy import Column, Integer, String, Text, create_engine
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker

Base = declarative_base()

class Skill(Base):
    __tablename__ = 'skills'
    id = Column(Integer, primary_key=True)
    name = Column(String(64), unique=True, nullable=False)
    code = Column(Text, nullable=False)  # Python snippet to execute

# Helper to get a DB session (SQLite file `skills.db` in project root)
engine = create_engine('sqlite:///skills.db')
Base.metadata.create_all(engine)
Session = sessionmaker(bind=engine)
3

Phase 3: Core agent API (spec → plan → execute)

In this step we expose a tiny Flask endpoint called /agent. It accepts a JSON payload with a prompt field, looks up the matching skill (we only have "echo" for now), and runs the skill's Python code with exec. The endpoint then returns the skill's output wrapped in a JSON object, mimicking the spec‑to‑plan‑execute cycle of a full agent.

The endpoint is deliberately simple: it treats the skill's code as a function named run that receives the user prompt. Using exec lets us load the code from the SQLite database at runtime without any extra imports, which is perfect for a minimal clone.

app.py

import json, sqlite3
from flask import Flask, request, jsonify

app = Flask(__name__)
DB_PATH = 'skills.db'

def load_skill(name):
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    cur.execute('SELECT code FROM skills WHERE name=?', (name,))
    row = cur.fetchone()
    conn.close()
    return row[0] if row else None

@app.route('/agent', methods=['POST'])
def agent():
    data = request.get_json(force=True)
    prompt = data.get('prompt', '')
    # For this demo we always use the "echo" skill
    skill_code = load_skill('echo')
    if not skill_code:
        return jsonify({'error': 'skill not found'}), 404
    # Prepare a sandbox dict where the skill will define a run() function
    sandbox = {}
    exec(skill_code, sandbox)
    result = sandbox['run'](prompt)
    return jsonify({'result': result})

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
4

Phase 4: Seed the echo skill

Now we create a tiny script that populates the SQLite database with a single skill named echo. The skill's Python code defines a run function that simply returns the prompt prefixed with "Agent says:". Running this script once will bootstrap the DB so the Flask server can retrieve the skill later.

The script is safe to run multiple times – it will replace any existing echo entry, ensuring the demo stays deterministic.

seed_skill.py

import sqlite3

DB_PATH = 'skills.db'
ECHO_CODE = '''def run(prompt):
    return f"Agent says: {prompt}"'''

conn = sqlite3.connect(DB_PATH)
cur = conn.cursor()
# Create table if it doesn't exist
cur.execute('''CREATE TABLE IF NOT EXISTS skills (
    name TEXT PRIMARY KEY,
    code TEXT NOT NULL
)''')
# Insert or replace the echo skill
cur.execute('INSERT OR REPLACE INTO skills (name, code) VALUES (?, ?)', ('echo', ECHO_CODE))
conn.commit()
conn.close()
print('Echo skill seeded into', DB_PATH)
5

Phase 5: Run & verify

With the server code and the skill seeded, we can fire up the demo. First start the Flask app, then run the seeder to ensure the DB contains the echo skill, and finally send a POST request with a sample prompt. The response should echo back the prompt with the "Agent says:" prefix, proving the spec‑to‑plan‑execute loop works.

All commands are shown below; they assume you are in the project root and have a Python virtual environment activated.

# 1. Install dependencies (run once)
python -m venv .venv
source .venv/bin/activate
pip install flask

# 2. Seed the echo skillpython seed_skill.py

# 3. Start the Flask server (in a separate terminal or background)
python app.py &

# 4. Give the server a moment to start, then test the endpoint
curl -X POST http://localhost:5000/agent \
     -H 'Content-Type: application/json' \
     -d '{"prompt":"hello world"}'

# 5. When done, stop the server
kill %1
