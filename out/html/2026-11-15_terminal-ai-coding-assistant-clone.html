Terminal AI Coding Assistant Clone

A lightweight TypeScript‑Node starter inspired by Qwen‑Code

Welcome to another official UVF IT guide. In the next 45 minutes you’ll spin up a tiny terminal‑based coding assistant that accepts a prompt, sends it to a free‑tier LLM endpoint, and prints the response – a minimal homage to Qwen‑Code’s core idea.

We’ll use plain Node.js with TypeScript, Express for a tiny local API, and SQLite to store a tiny history log. No paid APIs – the example uses the free HuggingFace Inference API for a small model.

Before you start

  • Node.js ≥22 and npm must be installed; older versions may fail TypeScript compilation.
  • The real Qwen‑Code ships with sophisticated multi‑modal agents; this clone only does a single‑turn text completion.
  • Free inference endpoints have rate limits – if you hit 429, wait a minute or switch to another model.

Phase 1: Scaffold Project

First we create a fresh folder and turn it into a Node.js project. TypeScript gives us static typing and a clean build step, while ts-node lets us run .ts files directly during development.

We also install a few runtime helpers – Express for a tiny HTTP wrapper (later) and better‑sqlite3 for fast, zero‑config SQLite access. All of this is done with a single npm command so you can copy‑paste it.

mkdir terminal-ai && cd terminal-ai
npm init -y
npm i -D typescript ts-node @types/node
npm i express better-sqlite3
npx tsc --init --rootDir src --outDir dist --esModuleInterop true --resolveJsonModule true --module commonjs --target es2022

Phase 2: Data Model (SQLite)

We need a tiny persistence layer to remember what the user asked and what the model replied. SQLite is perfect because it lives in a single file and needs no external server.

The helper below opens (or creates) a file called history.db, ensures a logs table exists, and exports two async functions: addLog(prompt, response) and getLogs() for later use.

src/db.ts

import Database from 'better-sqlite3';

// Open (or create) the SQLite file in the project root
const db = new Database('history.db');

// Ensure the logs table exists – id, prompt, response, timestamp
db.exec(`
  CREATE TABLE IF NOT EXISTS logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    prompt TEXT NOT NULL,
    response TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );
`);

export function addLog(prompt: string, response: string): void {
  const stmt = db.prepare('INSERT INTO logs (prompt, response) VALUES (?, ?)');
  stmt.run(prompt, response);
}

export function getLogs(): {id:number;prompt:string;response:string;created_at:string}[] {
  const stmt = db.prepare('SELECT * FROM logs ORDER BY created_at DESC');
  return stmt.all();
}

Phase 3: Core API (LLM call)

In this step we add the heart of the clone: an HTTP POST /complete endpoint that receives a user prompt, forwards it to a free LLM on HuggingFace, and returns the generated text. The endpoint also records each request and response in a tiny SQLite database so you can inspect the history later. Keeping the logic in src/server.ts lets us run the whole app with a single ts-node command.

src/server.ts

import express from 'express';
import fetch from 'node-fetch';
import Database from 'better-sqlite3';

const app = express();
app.use(express.json());

// Initialise SQLite DB and ensure a logs table exists
const db = new Database('history.db');
db.exec('CREATE TABLE IF NOT EXISTS logs (id INTEGER PRIMARY KEY AUTOINCREMENT, prompt TEXT, answer TEXT, ts DATETIME DEFAULT CURRENT_TIMESTAMP)');

// Helper to call HuggingFace inference API (free model)
async function callModel(prompt: string): Promise<string> {
  const token = process.env.HF_TOKEN;
  if (!token) throw new Error('HF_TOKEN env var not set');
  const response = await fetch('https://api-inference.huggingface.co/models/Qwen/Qwen2.5-Coder-7B-Instruct', {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ inputs: prompt, parameters: { max_new_tokens: 200 } })
  });
  const data = await response.json();
  return data?.generated_text || data?.error || 'No response';
}

app.post('/complete', async (req, res) => {
  const prompt = req.body.prompt;
  if (!prompt) return res.status(400).json({ error: 'Missing prompt' });
  try {
    const answer = await callModel(prompt);
    db.prepare('INSERT INTO logs (prompt, answer) VALUES (?, ?)').run(prompt, answer);
    res.json({ answer });
  } catch (e:any) {
    res.status(500).json({ error: e.message });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => console.log(`🚀 server on http://localhost:${PORT}`));

Phase 4: Run Locally

Now we fire up the service directly from TypeScript without a build step. By using ts-node we keep the workflow lightweight, and the only runtime requirement is the HuggingFace access token. Export the token in your shell, then start the server – you should see a friendly startup message.

export HF_TOKEN=your_huggingface_token_here
npx ts-node src/server.ts
5

Phase 5: Verify & Extend

With the server running, a quick curl request proves the endpoint works and returns JSON with an answer field. You can also peek at the SQLite file to confirm the request was logged. As a next step, wrap the call in a tiny CLI script that reads stdin, posts to /complete, and prints the result – turning the HTTP service into a true terminal assistant.

curl -X POST http://localhost:3000/complete \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "Write a one‑line Python hello world"}' | jq .answer
